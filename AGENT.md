# Project Context & Architecture Rules

## 1. Tech Stack & Core Libraries
- **Framework:** [Ví dụ: Next.js 15 (App Router) / FastAPI / Flutter]
- **Language:** [Ví dụ: TypeScript 5.x (Strict mode) / Python 3.12]
- **State Management:** [Ví dụ: Zustand (client state), TanStack Query v5 (server state)]
- **Database & ORM:** [Ví dụ: PostgreSQL + Prisma / Supabase]
- **Styling/UI:** [Ví dụ: Tailwind CSS + Shadcn/UI]

## 2. Directory Map (Where to look & put files)
- `src/app/` — Routing & page entry points only (keep business logic out).
- `src/features/[domain]/` — Feature-sliced modules (components, hooks, api, types for each domain).
- `src/components/ui/` — Reusable, stateless primitive UI components.
- `src/lib/` — Third-party SDK wrappers & singleton instances (`db.ts`, `auth.ts`).
- `src/stores/` — Global client stores (do NOT duplicate server data here).
- `src/types/` — Shared global TypeScript interfaces & Zod schemas.

## 3. Data Flow & Architectural Boundaries
- **API Pattern:** Client Components -> TanStack Query Hook -> Server Action / Route Handler -> Service Layer -> DB.
- **Strict Boundaries:**
  - UI components MUST NOT call database or `fetch` directly.
  - Cross-feature imports are forbidden; shared logic must be lifted to `src/lib/` or `src/types/`.
  - Validation MUST use Zod schemas defined in `src/types/schemas.ts` before touching DB.

## 4. Coding Conventions & Anti-Patterns
- **Naming:** `camelCase` for variables/functions, `PascalCase` for components/types, `kebab-case` for file names.
- **Error Handling:** Always return typed result objects `{ success: boolean, data?, error? }` from Server Actions; never throw raw errors to UI.
- **DO NOT:**
  - Do NOT use `any` type or `@ts-ignore`.
  - Do NOT install new npm packages without asking first.
  - Do NOT modify files inside `src/components/ui/` directly (generated by CLI).

## 5. Key Domain Entities (Mental Model)
- `User` -> belongs to `Workspace` (via `WorkspaceMember` with roles: `OWNER`, `ADMIN`, `MEMBER`).
- `Project` -> belongs to `Workspace`, contains multiple `Tasks`.
- Auth session is resolved via `getCurrentUser()` in `src/lib/auth.ts`.

## 6. Verification Commands
- Typecheck: `npm run typecheck`
- Lint: `npm run lint`
- Test single file: `npx vitest run [path/to/file]`
